# 智阅 ZhiYue 是什么

> 一份完整的软件说明：它解决什么问题、给谁用、能做什么、不能做什么。
> 功能实现状态的逐条清单见 [`PRODUCT.md`](PRODUCT.md)；需求规格见 [`FEATURES.md`](FEATURES.md)。

---

## 1. 一句话

**智阅是一个完全本地运行的 PDF / 图片阅读器，把你读不懂的段落交给 AI，并且能记住你在书页上做的每一个标记。**

它不联网也能读、能标注、能做文字识别；联网时它接一个你自己选的 AI 服务（自备 API Key），帮你翻译、解释、检索。

---

## 2. 它解决什么问题

| 你遇到的麻烦 | 智阅的做法 |
|---|---|
| 读外文 PDF / 论文，遇到生词长句要反复复制粘贴到翻译网站 | 直接划词，工具条上点「翻译」或「解释」，结果浮层流式返回，不离开书页 |
| 扫描版 PDF 是图片，选不了字、搜不了 | 内置离线 OCR 生成隐形文本层，之后和文字版一样可以划词、搜索 |
| 想把重要内容标记下来，但阅读器只能高亮，导出还得手工整理 | 文本层四种标记 + 图像层四种画笔工具，一键导出 Markdown / JSON |
| 读 PDF 想手写批注、画箭头、盖章 | 图像层标注：画笔、形状、便签、图章，支持撤销重做 |
| 看完想找「那句话在哪本书哪一页」 | 全局全文搜索（FTS5 + 中文分词），命中书 / 页 / 摘要，点击跳转并高亮 |
| 读双语材料，原文译文来回对照很累 | 对照阅读：左右分栏，译文保留原版式，随翻页联动 |
| PDF 的目录是错的 / 缺章节，想自己补 | 目录编辑：重命名、隐藏、加书签，**不改动原文件** |
| 担心阅读内容被上传到云端 | 全本地：书、标注、索引、设置都在你自己的磁盘上 |

---

## 3. 给谁用

- **读外文技术资料 / 论文的人**：划词翻译与解释是最高频的动作。
- **需要处理扫描件的人**：合同、旧书、影印本文档——OCR 让它们变成可搜索的文本。
- **做文献管理的人**：标注 + 导出 + 全文搜索，构成一个轻量的个人知识库。
- **在意隐私的人**：不希望把整本书上传到某个云阅读服务。
- **自备模型的人**：自己有功底的 API Key（DeepSeek / Kimi / 通义 / Ollama 等 OpenAI 兼容服务），不想再为 AI 阅读单独付费。

## 4. 一条完整的使用流程

```
导入 → 阅读 → 划词 → AI / 标注 → 搜索 → 导出
```

### 4.1 导入与书库

把 PDF 或图片拖进书库即可。**按文件内容哈希去重**——同一个文件从不同路径导入两次，只会有一本。
书库提供：封面缩略图、收藏、分类（可拖拽归类）、按类型 / 关键词筛选、阅读进度。

### 4.2 阅读

三种视图随时切换：**单页 / 双页滚动 / 双页翻阅**。支持缩放（桌面 Ctrl+滚轮、手机双指捏合）、翻页、目录树、缩略图轨；关掉再打开，回到上次那一页。

### 4.3 划词与 AI

选中文字后浮现工具条，提供 8 个动作：**翻译 / 解释 / 搜索 / 复制 / 高亮 / 下划线 / 删除线 / 笔记**。

AI 的能力：

- **流式对话**，Markdown 与 LaTeX 公式实时渲染
- **按书分会话窗**，历史持久化；可限制每次只带最近 N 轮历史
- **角色模板**：通用 / 学术 / 小说 / 技术 / 语言，可编辑、可另存自定义
- **截图识图**：框选页面区域直接问模型（多模态）
- **联网搜索**：内置搜索或第三方搜索端点，可抓取结果正文

### 4.4 标注

**文本层**：基于 PDF 字符盒的精确选区（支持跨行、反向拖拽），四种标记 + 颜色。

**图像层**：画笔、形状（箭头 / 矩形 / 椭圆）、便签、图章（签名图），可撤销重做，与页面一起拼合导出。

标注不只是画在屏幕上——它们存进数据库，侧栏可跳转、编辑、删除，并导出为 Markdown 或 JSON。

### 4.5 扫描件 OCR

扫描页自动识别；整页 OCR 生成**隐形文本层**，之后可以像文字版一样划词、搜索。

两种精度模式可选（高精度 / 快速）；低置信度行会半透明标记，可点击手工修正，修正后自动重入搜索索引。
另有预处理增强、90° / 180° 自动方向矫正、透视矫正。

### 4.6 全文搜索

SQLite FTS5 + jieba 中文分词（FTS5 原生对中文只能逐字切分）。文字版 PDF 直接索引，扫描页在 OCR 成功后增量入索引。

### 4.7 对照阅读（双语）

阅读区左右 50/50 分栏，左原文右译文，随翻页联动。译文由随包内置的 **RetainPDF** 引擎生成，**保留原版式**，正文可选中，也能在上面做标注。

### 4.8 目录编辑

PDF 目录只读是常态。智阅允许你重命名、隐藏、加书签——但这些**只存在本应用的库里**，PDF 文件本身不被修改（所以发给别人的仍是原始目录）。

## 5. 技术上有什么特别

- **重活在 Rust，界面在 Flutter**：PDF 渲染、OCR 推理、数据库、搜索索引、AI 网络请求、翻译编排全在 Rust 侧；Flutter 只负责绘制与交互。
- **完全离线可用**：OCR 模型随包内置（约 210MB），不联网也能识别扫描页。
- **BYOK**：AI 用你自己的 Key，协议兼容 OpenAI 格式，换供应商只改设置不改代码。
- **本地优先**：书库、标注、进度、会话、索引、设置全部存在本地 SQLite（WAL + FTS5）。
- **三平台**：Linux 桌面（deb / rpm / AppImage）、Windows 桌面、Android arm64。

## 6. 你的数据在哪

| 内容 | 位置（Linux 为例） |
|---|---|
| 书库、标注、进度、AI 会话、搜索索引、设置 | `~/.local/share/RBWA/rbwa.db` |
| OCR 模型 | `~/.local/share/RBWA/models/` |
| 译文产物与缓存 | `~/.local/share/RBWA/translated/<book_id>/` |

**API Key 只存在本地数据库里**，不写日志、不随诊断信息外传。唯一的网络流量是你主动发起的 AI / 搜索请求。

## 7. 明确做不到的事

诚实地列在这里，避免误期待：

| 限制 | 原因 |
|---|---|
| **翻译只能整本、目标语言固定简体中文** | 版式保留依赖引擎先解析全本结构；这是当前引擎的取舍，不是 UI 问题 |
| **翻译没有「逐页即时」效果** | 同上：要版式就必须整本 |
| 图片书没有原生文字层 | 需先做整页 OCR，之后靠 OCR 生成隐形文本层 |
| 嵌入（语义）搜索**未实现** | 设置项能存，检索管线没有做 |
| 目录编辑结果不写回 PDF | pdfium 没有写回目录的 API，改动只在本应用内可见 |
| 阅读时长统计 / 书摘 | 未实现 |
| 多书对比 / 双开 | 未实现 |
| Windows 版未做过完整桌面验证 | 能构建、核心逻辑已验证，界面尚待在真实桌面走一遍 |

## 8. 和别的阅读器比，区别在哪

- 相比通用 PDF 阅读器：多了**离线 OCR** 和**深度集成的 AI**（不是外挂一个侧边聊天框）。
- 相比云端文档服务：**数据不出本机**，没有账号体系，没有阅读时长上报。
- 相比划词翻译工具：翻译结果可以**原位保留版式**，而不是给一段纯文本。
- 相比笔记软件：直接读原件、在原件上标注，不需要先转格式。
