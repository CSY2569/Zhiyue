## 1. 这是什么

一个**完全本地**的文档阅读器：打开 PDF（文字版或扫描版）和图片，选中文字即可翻译、解释、搜索；
可以在文本层和图像层上做标注；内置离线 OCR；接一个 OpenAI 兼容的 AI 服务（BYOK）做对话与识图。

全部重活（PDF 渲染、OCR、数据库、搜索索引、AI 网络请求、翻译编排）在 Rust 侧；Flutter 只负责绘制与交互。

## 3. 逐域说明

### 3.1 书库

- 导入 PDF / 图片；**按内容哈希去重**（同一文件换路径再导入不会重复入库，`api.rs:336 dedupe_books_by_content_hash`）。
- 网格展示 + 封面缩略图（缺封面可修复，`repair_covers`）；收藏；删除（级联清理标注、索引、翻译产物）。
- 分类：增 / 删 / 改 + 拖拽归类。
- 筛选：视图 + 类型 + 关键词；排序与批量操作。
- 阅读进度：每本书记录页码 / 缩放 / 视图模式，重开即恢复。

### 3.2 阅读器

- 三种视图：单页 / 双页滚动 / 双页翻阅，可互相切换且保持当前页。
- 缩放（Ctrl+滚轮或捏合）、翻页（滚轮 / 工具条 / 翻页键 / 边缘点按）。
- 侧栏：目录树（只读）、缩略图轨、标注列表；宽度可拖拽并持久化。
- 虚拟滚动 + 位图 LRU 缓存，按字节预算控制内存。

### 3.3 文本层标注

- 基于 pdfium 字符盒的精确选区：支持正反向拖拽、跨行。
- 四种标记：高亮 / 下划线 / 删除线 / 笔记；颜色可选。
- 浮动工具条提供 8 个动作：翻译 / 解释 / 搜索 / 复制 / 高亮 / 下划线 / 删除线 / 笔记。
- 标注侧栏可跳转、编辑、删除；导出 **Markdown** 或 **JSON**。

### 3.4 图像层标注

- 四种矢量标记：画笔（自由笔迹）、形状（箭头 / 矩形 / 椭圆）、便签（浮动文本框）、图章（签名图）。
- 撤销 / 重做；调色、线宽；标记以 JSON 存库（`image_annotations`）。
- 支持把页面位图与标记拼合成图片导出。

### 3.5 离线 OCR

- 扫描页自动检测；整页识别生成**隐形文本层**，之后可像文字版一样划词。
- 两种精度模式：`high_precision`（server 模型，准）与 `fast`（mobile 模型，快/小）。
- 按 `(书, 页, 模式)` 缓存识别结果；引擎懒加载，不用不占内存。
- 低置信度行（< 0.8）半透明标记 + 计数提示；可点击手动修正，修正后自动重入搜索索引。
- 预处理增强（低对比度拉伸 / 模糊锐化）、90° 自适应重扫、180° 方向矫正。
> ⚠️ **模型文件不在仓库**：需 `bash scripts/download_ocr_models.sh --all`（高精度 ~195MB + 快速 ~15MB）。缺失时该功能报「模型未安装」而不是崩溃。

### 3.6 AI

- **流式对话**：OpenAI 兼容协议，逐字输出，Markdown + LaTeX（含公式）渲染。
- **按书分会话窗**：每本书一个线程，历史持久化；追问可带全书上下文或仅当前窗口上下文。
- **角色模板**：通用 / 学术 / 小说 / 技术 / 语言 / 自定义；内置模板可编辑覆盖，也可保存多个自定义模板。
- **识图**：自由框选截图 → 合成 PNG → 送多模态模型。通用模型声明支持图片时直接用通用通道，否则走独立视觉配置。
- **联网搜索**：两种接入方式 —— 内置搜索（Responses / Anthropic 两种线协议）或第三方端点（Bocha 兼容 / DeepSeek Tools），可选抓取前 N 条网页正文。
- **推理模式**：可开 `reasoning_effort`（low / medium / high）；温度可调（0–2）。
- **API 协议**：`chat_completions` 或 `responses`，后者被供应商拒绝时自动回退。

### 3.7 全文搜索

- SQLite FTS5 + jieba 中文分词（FTS5 原生对中文只做逐字切分）。
- 文字版 PDF 直接索引；扫描页 OCR 成功后增量入索引；导入后后台预构建。
- 全局搜索给出命中书 / 页 / 摘要片段，点击跳转并高亮页内命中词。
- 失败索引有终态标记，不会无限重试。

### 3.8 对照阅读（翻译）——当前的真实能力

阅读区左右 50/50 分栏，左原文右译文，随翻页联动。引擎是随包内置的 **RetainPDF** 管线（独立子进程，MIT）。

**能做的**：整本书一次性翻译；保留原版式的译文 PDF（正文可选中）；译文页上同样可以划词与标注（标注按窗格隔离）；术语表；2GB LRU 缓存；按需导出译文 PDF。

**不能做的（重要）**：
- ❌ **只有整本粒度**。`TranslationMode` 里的「随进度」「手动」两个值仅存在于数据结构与 DB 兼容层，引擎路径不消费（`rust/src/translate/job.rs:19`）。
- ❌ **目标语言固定简体中文**（上游局限）。设置里虽有 `translate_target_lang` 字段，桌面 RetainPDF 路径不生效。
- ❌ 桌面端无法在应用内卸载引擎（随包内置）。

### 3.9 设置项全景

设置页共 6 个分区，全部持久化在 SQLite 的 `settings` 表（key-value，value 为 JSON）。

| 分区 | 主要内容 |
|---|---|
| 外观 | 主题（明 / 暗 / 跟随系统）、阅读主题与配色 |
| 阅读器 | 目录默认展开、OCR 识别精度（高精度 / 快速）、面板宽度 |
| 服务与模型 | API 协议、Base URL、API Key、模型 ID、模型能力（是否支持图片）、独立视觉配置（URL / Key / 模型） |
| 翻译 | 目标语言、自定义语言、术语表、翻译提供方 |
| 搜索 | 联网搜索开关、搜索方式（内置 / 第三方）、内置协议（Responses / Anthropic）、第三方协议（Bocha / DeepSeek）、API 基地址与 Key、抓取正文条数 |
| 嵌入搜索 | ⛔ **仅持久化，未实现**：开关、Base URL、API Key、模型、向量库 URL / Key / 集合 |

> 🔒 **`ai_config` 是后续测试的基准数据**：上面「服务与模型 / 翻译 / 搜索 / 嵌入搜索」四项合起来是 `settings` 表里 `key='ai_config'` 的一个 JSON（由 `rust/src/models/ai.rs` 的 `AiConfig` 反序列化，30+ 字段，全部带默认值）。
> **改动数据库结构或重构代码时，必须保证这份 JSON 能原样读回、字段不丢失。** 逐字段说明见 [`DATA_MODEL.md`](DATA_MODEL.md) §AI 设置。
