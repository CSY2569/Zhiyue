二、各阶段详解与对应技术

阶段 1 · 触发与队列编排(Flutter / Dart)

工具栏「对照阅读」按钮切换 translationPaneProvider:阅读区变为 50/50 左右分栏(左原文 PdfPageScroll,右译文 TranslatedColumn);若当前是双滚/双翻,自动切为单页并记住原模式(modeBefore),关闭时恢复。

翻译的发起有三种模式(设置 translation_config.mode):

  • 整本:startBook 将 1..N 入队,先经 getTranslatedPages 一次批量读回已译页(跳过缓存);
  • 随进度(默认):每次翻页 onVisiblePages 入队「可见页 + 后两页」;
  • 手动:仅右页卡片上的「翻译本页」按钮。

队列 TranslationQueueNotifier 负责并发池(配置 concurrency,夹取 1–8)、取消(cancel 停发新页)、失败页记忆(_failed,不自动重试、可手动重试)、切书后台行为(cancel / pause_resume / continue,恢复依赖缓存跳过)。调用翻译前会等待配置异步加载完成(await translationConfigProvider.future,消除开书瞬间的竞态)。

DartRiverpod Notifier / AsyncNotifier StreamSink 消费流go_router(设置页跳转) window_manager

阶段 2 · 页级缓存快路径(Rust / SQLite)

每次翻译前先查 page_translation_cache:主键 (book_id, page, 配置目标语言, provider),命中且 source_hash 带当前抽取器版本戳(v7:sha256)即直接返回,不发起任何网络请求。版本戳让抽取算法升级后旧结果自动失效重译;「中英互译」按页解析生效语言存于载荷、键用配置语言,保证读写一致。

读取同时刷新 last_accessed_at(LRU 依据)。导出与对照视图使用同一缓存,且同样拒绝过期行。

rusqlite (bundled SQLite, WAL) sha2 指纹 EXTRACTOR_VERSION 版本戳 serde_json 载荷 非可重入 Mutex 纪律(cache_key_with 复用连接)

阶段 3 · 段落抽取(Rust / pdfium)

在独立 pdfium 文档句柄上执行(进程级 PDFIUM_LOCK 串行——pdfium 非线程安全,并发调用会静默返回空文本),绝不阻塞阅读器渲染。管线:

  1. 字符采集 collect_page_chars:每个字符的几何(tight_bounds → 归一化矩形,顶左原点)与字体元数据(字体名、symbolic 标志、缩放/未缩放字号、旋转角、连字符标志)。
  2. 行聚类 cluster_lines:基线中心 y 距离(0.6×行高容差)聚类;空格吸附最近行;丢弃控制字符。
  3. 阅读顺序 order_for_reading:扫描 0.35–0.65 的栏槽检测双栏(无跨栏线才拆),左栏先读。
  4. 段落合并 fallback_paragraphs:垂直间隙(> 中位行高×0.7)与首行缩进分段;窄且居中的行判定为显示公式,独立成段( prose↔公式交界强制断开)。
  5. 文本修复 join_paragraph_text / normalize_text:行尾连字符+小写续行还原(continua- / tion → continuation)、CJK 直接拼接、连字归一(ﬁ→fi)、软连字符剔除。
  6. 噪声剔除 is_noise:上下 8% 边距带 + 页码样式("− 3 −"、"Page 12")+ 相邻页同位置重复 → 页眉/页脚/页码剔除。
  7. 公式识别:字符级信号(is_math_font_name 数学专用字体表 + 任意 *MATH* 族通配 + TX/PX/WASY;is_strong_math_char 60+ 运算符/希腊字母;缩放比偏离中位 = 上下标;symbolic 字体)聚成公式区;整段公式四信号判定 is_whole_paragraph_formula(≥80% 纯符号 / 数学字母占比 ≥60% 且长词 ≤1 / 居中短块+数学信号 / 全数学字体算子名公式:math_ratio ≥ 0.9 + 长词 ≤6 + 符号占比 ≥0.3),外加 text_looks_like_formula 内容门控保护 LaTeX 正文。
  8. 不可恢复符号:PDF 缺 ToUnicode 时行内公式符号在抽取文本中留下空洞("(, )");这类段落仍正常送翻、正常重绘——只保留整体判定为公式的段落原像素,不整段保留原文。
  9. OCR 回退:无文字层且开启 auto_ocr → 页面光栅 → rapidocr(页级 OCR 缓存)→ 按行距并入同一重建流程;置信度 <0.8 标低置信。
pdfium-render 0.9(thread_safe + PDFIUM_LOCK) 基线聚类 / 中位数阈值 字体元数据公式识别 rapidocr-core + onnxruntime 页级 OCR 缓存

阶段 4 · 翻译提供方(Rust / DeepL 与 OpenAI 兼容 LLM)

统一 Provider 接口 translate_segments,按 ≤20 段一批:

  • DeepL:POST /v2/translate,tag_handling=xml + ignore_tags 让公式占位符原样穿透;术语表经 API 创建并按语言对持久化 glossary_id;语言码映射(中文→ZH…);key 后缀 :fx 自动选免费端点。
  • OpenAI 兼容 LLM(独立配置或复用 AI 设置):要求严格对齐 JSON 数组 [{"i","t"}],缺项/错位对缺失编号逐段重试 ≤3 轮;不可信文本以 <text> 包裹防提示注入;失败段保留原文标 Failed。
  • 公式占位符保护:内联公式替换为随机前缀令牌 ⟨F{时间纳anos}{pid}-MATH_n⟩(防书内伪造),回填时校验「恰好出现一次且未变」,失败标「公式需核对」或回退原文本。
  • 传输 post_with_retry:429/5xx 指数退避 + Retry-After,≤3 次;4xx 快速失败并截断展示错误体。
  • 目标语言:沿用 AI 设置;「中英互译」按每页 CJK 占比(cjk_ratio)解析为中文或英文。
reqwest (rustls-tls, JSON) 手写重试/退避 严格索引对齐协议 XML ignore_tags 术语表 glossary <text> 注入防御

阶段 6 · 版式保留渲染(Rust / lopdf + pdfium)—— 本功能的核心

把一页译文合成为「原页背景 + 原位矢量译文」的 PDF,再光栅化成位图给右页显示:

  1. 背景:原页按 dpi 渲染(24MP 像素上限),每个文本段落的行矩形涂白(纵向 padding 覆盖高出行的数学字形),JPEG q90 编码为 DCTDecode 整页 XObject —— 图表、公式、表格、页眉页脚、分栏结构全部原样保留。
  2. 原位译文:每个文本段落在其行矩形并集内绘制 —— 宽度=矩形宽,字号按行高中位数×0.82 估算(6–28pt),超高按 ×0.9 收缩至 5.5pt;wrap_text 以真实字体量宽断行(拉丁在空格断、CJK 任意断)。
  3. 真矢量文本:lopdf 构造 Type0 / Identity-H CID 字体 + /ToUnicode CMap + /W 宽度表,subsetter 运行时子集化内置 Noto Sans SC(31k 字形,含希腊;OFL 许可随源码分发)——译文可选中、可检索,PDF 体积小。
  4. 字形回退 FALLBACK_GLYPHS(约 70 项,递归链):字体缺失的数学符号(∘ ≔ ⊔⊓ ℝℤℚ ⟶ ₁₂ₙ ϑ…)映射到存在的形近字符,杜绝 .notdef 空洞。
  5. 保留规则:仅整段公式(ParagraphKind::Formula)不涂白不绘制 —— 原像素即最高保真;其余文本(含抽取丢失行内符号的段落)一律涂白重绘译文。译文超出 footprint 被截断时,末行补 '…' 标记,不静默丢失。
  6. 光栅化:合成 PDF 经 pdfium 按 dpi 3.0 渲染(背景与合成同比例,1:1 像素无重采样模糊),实测 A4 约 1785×2525 / 210ms。
  7. 回退布局:占位页、旧缓存行或光栅失败时降级为紧凑单栏重排(锚点 + 量宽排版,公式段以原文文本重排)。

四、一页的旅程(随进度模式,时序)

  1. 用户翻到第 12 页 → 阅读器监听 viewerProvider 触发 onVisiblePages(book, [12])。
  2. 队列等待配置就绪 → 目标集 {12, 13, 14} → 一次 getTranslatedPages 得已译集 → 差集入队(跳过失败记忆页)。
  3. 并发池(默认 2–3)逐页调 translatePage 流;核心先查缓存 —— 第 12 页已译则秒回。
  4. 第 13 页未译:抽取 → 25 段(其中 4 段判为公式保留)→ 21 段分两批 POST 到 LLM → 严格对齐 + 占位符保护 → 组装 → 计算指纹(v7:sha256)→ 写缓存 → 发完成事件。
  5. 队列自增 revision → 右页的 translatedPageImageProvider 失效重渲染:原页光栅涂白 + 译文原位绘制 + pdfium 3x 光栅 → 双页右栏换上新译文。
  6. 用户点工具栏「导出译文 PDF」→ 1..N 组装(未译页占位)→ 流式进度 → SnackBar 给出路径,可一键复制。

五、已知限制与设计取舍

无 ToUnicode 的数学字体:部分 LaTeX PDF 的数学字形(γ、φ、f₁)没有文本映射,抽取层拿不到 —— 对应位置在译文中留空("(, )" 空洞)。这类段落仍正常送翻与重绘(不整段保留原文);整体判定为公式的段落由覆盖层保留原像素,是保真的主要手段。后续可探索按字形反查字体编码恢复。
  • 重排溢出:译文超过原段落矩形时字号收缩至 5.5pt 下限,仍放不下则截断并补 '…'(不跨页增长,保证页码对齐)。
  • 扫描页:依赖 OCR,置信度 <0.8 标低置信;无文字层且未开 OCR 时报可读错误。
  • 公式保真边界:检测依赖字体命名/符号/缩放信号,极少数正文用数学字体排版的书以长词门控 + 符号占比保护,仍可能有个别段落被保守保留为原文。
  • 翻译质量:LLM 逐段直译,抽取丢失行内符号的段落译文会在对应位置留空(LLM 只能尽力补全语义);术语表可约束译名一致性。
