## 1. 边界说明

**跨边界只认 `rust/src/api.rs` 的 `pub fn`。** `flutter_rust_bridge.yaml:8` 把 `rust_input` 钉成 `crate::api`，只有这一个模块里的公开函数会被导出。`api.rs:1-13` 的模块文档写明它是 single aggregation point，Dart 侧永不直接调 `pdf` / `ai` / `db`。

**Dart 侧只经 `lib/data/repositories/`。** `lib/data/repositories/reader_repository.dart:191` 注释明写「this repository is the only layer that touches `lib/src/rust/*`」。UI / features 层不得 import 生成物。

- 现存唯一例外（启动早于 ProviderScope）：`lib/main.dart:32` → `lib/platform/desktop/desktop_host.dart:42` 直接调 `rust.initCore()`，经 `PlatformHost` 抽象而非 repository。
- 生成物禁手改：`rust/src/frb_generated.rs`、`lib/src/rust/**`（`api.dart`、`frb_generated.dart`、`frb_generated.io.dart`、`frb_generated.web.dart`、`models/*.dart`、`pdf/types.dart`、`ocr.dart`）。文件头均带 `@generated by flutter_rust_bridge@ 2.12.0`。

**FRB 版本三处硬绑 2.12.0**，升级必须三处同改并重跑 codegen：

| 位置 | 现值 |
|---|---|
| `rust/Cargo.toml:24` | `flutter_rust_bridge = "=2.12.0"` |
| `pubspec.yaml:15` | `flutter_rust_bridge: 2.12.0` |
| codegen CLI | `cargo install flutter_rust_bridge_codegen --version 2.12.0 --locked`（`docs/archive/DEPENDENCIES.md:52`） |

生成物回写该版本：`lib/src/rust/frb_generated.dart:71`（`codegenVersion => '2.12.0'`）、`rust/src/frb_generated.rs:40`（`FLUTTER_RUST_BRIDGE_CODEGEN_VERSION`）。

**跨边界类型面**：数据结构在 `rust/src/models/**`（`rust/src/models/mod.rs:7-11` 列出 book/category/progress、annotation、ai、translate 的里程碑归属）。`api.rs` 内另有 17 个 `pub struct`（43 / 218 / 715 / 725 / 734 / 1037 / 1084 / 1090 / 1213 / 1318 / 1866 / 1888 / 2029 / 2046 / 2225 / 2269 / 2533），其中 14 个是「结果信封」，见 §3。

**feature 门控**：`rust/Cargo.toml` 的 `[features]` 为 `default = ["pdf", "ai", "ocr"]`；`api.rs` 内共 19 处 `#[cfg(feature = "ai")]` 与 16 处 `#[cfg(not(feature = "ai"))]`，两两成对。

**必须保住的数据**：`settings` 表的 `ai_config` KV。读写点在 `api.rs:1305`（`settings_repo::get_json`）与 `api.rs:1311`（`set_json`），另被 `rust/src/translate/mod.rs:208`、`rust/src/translate/text_translate.rs:655` 读取。数据库迁移与历史文档口径都不必向后兼容，唯独这条 JSON 丢了 AI 侧无法测试。

## 3. 错误约定

**不返回 `Result`。** 全库没有任何一条 `pub fn` 以 `Result` / `AppResult` 为返回类型（校验命令见 §7）。`api.rs:2142-2143` 的分节注释给了口径：`All error surfaces use the sentinel pattern (an error: Option<String> field) -- never Result.`

**信封结构体范式**：`InitResult`（`api.rs:43`）是最小样板 —— `ok: bool` + 业务字段 + `error: Option<String>`。共 14 个信封带 `error` 字段：

| 结构体 | 定义行 | 结构体 | 定义行 |
|---|---|---|---|
| `InitResult` | 43 | `AnnotationCreateResult` | 1084 |
| `ImportResult` | 218 | `ExportResult` | 1090 |
| `OpenBookResult` | 715 | `ImageMarkCreateResult` | 1213 |
| `PageRenderResult` | 725 | `AiThreadCreateResult` | 1318 |
| `OutlineResult` | 734 | `ScanPageResult` | 1866 |
| `CharBoxResult` | 1037 | `SearchResult` | 2046 |
| `TranslatedPageBitmap` | 2225 | `GlossaryResult` | 2533 |

**为什么不用 `Result`**：FRB v2 把 Rust `Err` 映射成 Dart 侧抛异常，UI 每个调用点都得包 try/catch，且异常信息只剩字符串、丢掉业务字段（比如导入失败时仍想拿到解析出的书名）。信封法则让 Dart 拿到普通不可变对象，由 UI 决定是弹错还是降级；repository 层可以就地兜底（例：`lib/data/repositories/library_repository.dart:18-25` 对 `listBooks` 加 `catch (_)` 返回空表）。

**集合失败返回空 vec**：`list_books`（`api.rs:247-250`）注释即 `Returns an empty vec on error (the UI shows the empty-state guide)`，实现是 `book_repo::list(&conn).unwrap_or_default()`。同理 `list_categories`(675)、`list_annotations`(1114)、`list_image_annotations`(1220)、`list_ai_threads`(1325)、`list_ai_messages`(1331)、`list_reading_progress`(867)。

**其余哨兵值**：

- `i32` 布尔语义：`1` 成功 / `0` 失败（`set_setting:187`、`delete_book:604`、`clear_translation_artifacts:2150` 的 `.map(|_| 1).unwrap_or(0)`）。
- id 语义：失败返回 `-1`（`create_ai_thread` 的 `id: -1, error: Some(...)`，`api.rs:1351-1355`；`add_translation_glossary` 的 `.unwrap_or(-1)`，`api.rs:2569`）。
- `Option<T>` 只表示「没有」，不表示「出错」：`get_book:255`、`get_progress:860`、`get_page_ocr:1881`、`get_page_text_translation:2428`。
- 流式命令的错误走 sink：`sink.add_error(String)`（`api.rs:1723`、`api.rs:1726`）；整书翻译则把错误塞进最后一个事件（`rust/src/translate/job.rs:151-162`）。

## 4. 并发约定

**阻塞重活必须 `tokio::task::spawn_blocking`。** async fn 跑在 tokio worker 线程上，同步的 pdfium 调用 / OCR 推理 / 外部进程 / 大文件 IO 直接写在里面会堵住执行器，其它命令的 Future 一起卡死。现存 3 处（全库 `grep -rn spawn_blocking rust/src/` 的全部结果）：

| 位置 | 包住的阻塞工作 |
|---|---|
| `api.rs:1060` | `extract_translated_text` 里的 `crate::pdf::extract_text_file(&path, page)`（pdfium 文本遍历） |
| `api.rs:2327` | `render_translated_page` 里的 `crate::pdf::render_page_file_to_width(...)`（pdfium 栅格化） |
| `rust/src/translate/job.rs:150` | 整书翻译的 `run_job(book_id, &mut on_event)`（外部引擎进程，分钟级） |

范式照抄 `api.rs:1059-1070` 的三层 match：`Ok(Ok(v))` 正常、`Ok(Err(e))` 业务错、`Err(join_err)` 任务自身失败（各自映射成信封的 `error: Some(...)`，失败时业务字段给空 vec / 0）。

> 反例提醒：`extract_text`（`api.rs:1101`）虽是 `async` 且在注释里写着 must not block the UI，实现里却直接同步调 `current_boxes(page)`，没有 spawn_blocking（待核：是否 pdfium 锁导致不便异步化）。加新命令时不要照抄它。

**feature 门控成对写 `cfg` 桩。** 范式是 `translate_book`（`api.rs:2239-2261`）：

```rust
pub async fn translate_book(book_id: i64, sink: StreamSink<BookTranslateEvent>) {
    #[cfg(feature = "ai")]
    { /* 真正实现 */ }
    #[cfg(not(feature = "ai"))]
    { let _ = book_id; /* 返回默认值 / 空结构 */ }
}
```

必须成对的原因：绑定签名由 `api.rs` 的语法形态直接生成，`cfg` 不对称会让 `--no-default-features` 构建少一个函数，Dart 侧（单套生成物）在运行期找不到绑定。配套写法是 `let _ = param;` 消掉 unused 警告（例 `api.rs:2413`、`api.rs:2470`、`api.rs:2500`）。

**全局状态用 `OnceLock` / `Atomic`**，不要用 `static mut` 或 Mutex 跨 await 持有：`INITIALIZED`（`api.rs:34`）、翻译任务的 `RUNNING` / `CANCEL`（`rust/src/translate/job.rs:147-148` 附近）。

## 5. 新增一条命令的端到端五步

以「给书库加一条 `count_books_by_type(book_type: BookType) -> i64`」为例，每一步的文件与命令都是现成的。

**第 1 步 · 模型层**（只有跨边界的新类型才需要）：`rust/src/models/<domain>.rs` 加 `pub struct` / `pub enum`，并在 `rust/src/models/mod.rs` 里 `pub mod` 声明（现有：`ai.rs` / `annotation.rs` / `book.rs` / `progress.rs` / `translate.rs`）。FRB 只接受无 lifetime、无泛型的 plain 类型；跨边界 `enum` 建议 `#[derive(Clone, Copy, ...)]`（`OcrMode` 即如此，其 `as_str` 在 `api.rs:1856`）。

**第 2 步 · `rust/src/api.rs`**：在对应里程碑分节里加 `pub fn` / `pub async fn`。三条硬规矩：

1. 返回信封结构体，不返回 `Result`（§3）；新信封就定义在函数上方，与 `CharBoxResult`（`api.rs:1037`）同风格。
2. 重活 `spawn_blocking`（§4）。
3. feature 相关就成对写 `cfg`（§4）。

**第 3 步 · 子系统实现**：真正的逻辑放 `rust/src/<subsystem>/`（`pdf` / `ai` / `ocr` / `search` / `translate` / `export`）或 `rust/src/db/repository/<x>.rs`（现有 11 个：`ai` / `annotation` / `book` / `category` / `image_annotation` / `ocr` / `progress` / `search` / `settings` / `text_translation` / `translate`）。`api.rs` 里只留参数转换 + 信封包装，范式见 `create_annotation`（`api.rs:1123-1145`）。

**第 4 步 · codegen**（在仓库根执行）：

```bash
flutter_rust_bridge_codegen generate
```

配置读 `flutter_rust_bridge.yaml:7-10`：`rust_input: crate::api` → `dart_output: lib/src/rust`、`rust_output: rust/src/frb_generated.rs`。产物是 `rust/src/frb_generated.rs` 与 `lib/src/rust/**`，必须与 `api.rs` 一起提交（`docs/archive/BRANCHING.md:66`、`docs/archive/BRANCH_SPLIT_PLAN.md:248`、`docs/PLATFORMS.md:55` 都复述了这条）。

**第 5 步 · repository**：`lib/data/repositories/<x>_repository.dart` 加转发方法，形如 `Future<T> foo(...) => rust.foo(...)`（现有 6 个 repository：`ai` / `library` / `reader` / `search` / `settings` / `translation`）。UI 只依赖 repository，不 import 生成物（§1）。

> **警示：改了 `api.rs` 不跑 codegen，编译期不会报错，运行期直接崩。** `lib/src/rust/frb_generated.dart:73-74` 把生成时的 Rust 源码哈希写死成 `int get rustContentHash => 507000550;`，Rust 侧 `frb_generated.rs` 也带自己的哈希，`RustLib.init()` 时两边比对，不一致就抛 hash 不匹配；同时 `frb_generated.dart:71` 的 `codegenVersion => '2.12.0'` 参与同一轮校验。症状是「Flutter 一启动就炸、Rust 代码本身没问题」，很容易误判成别的原因。
